# implementer

把已拆分好的任务清单，逐项落成代码改动。

## 必要前提

1. **奥卡姆剃刀**：如无必要，勿增实体。只实现任务清单写明的改动，不添加清单之外的函数、数据结构、配置或「顺手改进」。

## 工作流程

### 1. 了解任务全貌

读取 `docs/dev-docs/<开发序号>/` 下本次任务的开发文档与流程图，即 `<标题>开发文档.md` 与同目录的 `<标题>流程图.md`，据此了解本次任务的全貌。若开发文档或流程图缺失，先回到 `dev-doc-writer` 阶段补齐，不自行脑补设计。

### 2. 按执行顺序逐项实现

执行列表任务前先基于 `main` 创建新任务分支，本阶段的全部子任务改动都在该分支上提交；禁止在 `main` 分支上反复 commit；
读取本次开发序号对应的任务目录 `docs/dev-docs/<开发序号>/task-list/`：
- 执行顺序取自 `执行顺序.md`，按其给出的顺序逐步推进，不自行改序；
- 逐个读取任务文件 `<编号>-<任务标题>.md`，按其「工作区」「验收标准」与「实现内容」完成代码编写；
- 执行每个子任务时先检查其工作区：工作区**为空** → 自行发挥；工作区**非空** → 先分析现有代码是否符合任务设计，若不符合，则依据任务设计修改现有代码；
- 只改任务声明的工作区：**读写工作区**可新增或修改，**只读工作区**只读不改；
- 任务完成并达到其「验收标准」后，再标记该任务完成；
- 每完成一项子任务，生成一份任务报告 `docs/dev-docs/<开发序号>/task-report/<编号>-<任务标题>.md`，开发序号取该任务所属开发文档的序号；报告内容须包含：
  - **修改的信息**：本次改了什么、为何修改（对应任务设计）；
  - **修改的文件与文件内位置**：文件路径及具体位置（行号、函数名或段落）；
  - **检查结果**：对照本任务「验收标准」逐项核对的结论；
- 每完成一项任务，立即提交一次 commit：提交信息由该任务内容总结而来，长度不超过 128 字符；任务报告随该任务的 commit 一并提交；
- 每次 commit 后随即执行一次 push。

### 3. 函数的编写

函数 / 方法的编写遵循函数的设计规则。

**参考文件**：本 Skill 附带 `references/function-design-rules.md`（公有接口设计规范、伪代码实例、校验规则）。此处仅**显式声明其存在**；**仅在编写函数时才读取该文件内容**，其余阶段不展开其正文。

**调用关系规则**：本 Skill 附带 `references/call-relationship-rules.md`（同模块 / 跨模块的方法调用方式与依赖注入约束）。此处仅**显式声明其存在**；**仅在编写方法间的调用时才读取该文件内容**，其余阶段不展开其正文。

**资源生命周期规则**：本 Skill 附带 `references/resource-lifecycle-rules.md`（对象销毁时独占资源的释放责任、释放顺序与借用 / 共享引用处理）。此处仅**显式声明其存在**；**仅在编写对象销毁、资源获取或释放相关代码时才读取该文件内容**，其余阶段不展开其正文。

### 4. Rust 项目的额外约束

实现语言为 Rust 时，还须遵循 Rust 全局约束。

**参考文件**：本 Skill 附带 `references/rust-global-constraints.md`。此处仅**显式声明其存在**；**仅在编写 Rust 代码时才读取该文件内容**，其余阶段不展开其正文。

其他语言暂不提供额外约束文件，沿用第 3 步的函数设计规则。

### 5. Git 与 gh 命令

本阶段的创建分支、提交 commit、执行 push 等操作均通过 git / gh 命令完成。

**参考文件**：本 Skill 附带 `references/GitHub-CLI.md`（gh 命令参考）与 `references/GitHub-submit.md`（Conventional Commits 提交规范与 Git 安全约束）。此处仅**显式声明其存在**；**仅在需要执行 git 或 gh 命令时才读取这些文件内容**，其余阶段不展开其正文。

## 约束

- 代码产物只写入任务声明的工作区内；任务报告是唯一例外，固定写入 `docs/dev-docs/<开发序号>/task-report/`，不新增其他文件或目录。
- 严格按任务清单推进，不做清单之外的重构或「顺手改进」。
- 开发文档、流程图或任务清单缺失时，回到上一阶段补齐，不自行脑补。
- 未达到「验收标准」的任务不得标记完成；任务报告缺失或未覆盖「修改的信息」「修改的文件与文件内位置」「检查结果」三项的，同样不得标记完成。
