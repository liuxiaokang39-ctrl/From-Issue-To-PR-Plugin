# implementer

把已拆分好的任务清单，逐项落成代码改动。

## 必要前提

1. **奥卡姆剃刀**：如无必要，勿增实体。只实现任务清单写明的改动，不添加清单之外的函数、数据结构、配置或「顺手改进」。

## 工作流程

### 1. 了解任务全貌

读取 `docs/dev-docs/` 下本次任务的开发文档与流程图，即 `<序号>-<标题>开发文档.md` 与同序号的 `<序号>-<标题>流程图.md`，据此了解本次任务的全貌。若开发文档或流程图缺失，先回到 `dev-doc-writer` 阶段补齐，不自行脑补设计。

### 2. 按执行顺序逐项实现

执行任务前先基于 `main` 创建新任务分支，本阶段的全部子任务改动都在该分支上提交；禁止在 `main` 分支上反复 commit；
读取本次序号对应的任务目录 `docs/dev-docs/<序号>/`：
- 执行顺序取自 `执行顺序.md`（由 `task-planner` 的拓扑排序脚本生成），按其给出的顺序逐步推进，不自行改序；
- 逐个读取任务文件 `<编号>-<任务>.md`，按其「工作区」「验收标准」与「实现内容」完成代码编写；
- 只改任务声明的工作区：**读写工作区**可新增或修改，**只读工作区**只读不改；
- 任务完成并达到其「验收标准」后，再标记该任务完成；
- 每完成一项任务，立即提交一次 commit：提交信息由该任务内容总结而来，长度不超过 128 字符；
- 每次 commit 后随即执行一次 push。

### 3. 函数的编写

函数 / 方法的编写遵循函数的设计规则。

**参考文件**：本 Skill 附带 `references/function-design-rules.md`（公有接口设计规范、伪代码实例、校验规则）。此处仅**显式声明其存在**；**仅在编写函数时才读取该文件内容**，其余阶段不展开其正文。

### 4. Rust 项目的额外约束

实现语言为 Rust 时，还须遵循 Rust 全局约束。

**参考文件**：本 Skill 附带 `references/rust-global-constraints.md`。此处仅**显式声明其存在**；**仅在编写 Rust 代码时才读取该文件内容**，其余阶段不展开其正文。

其他语言暂不提供额外约束文件，沿用第 3 步的函数设计规则。

## 约束

- 产物只写入任务声明的工作区内，不新增任务之外的文件或目录。
- 严格按任务清单推进，不做清单之外的重构或「顺手改进」。
- 开发文档、流程图或任务清单缺失时，回到上一阶段补齐，不自行脑补。
- 未达到「验收标准」的任务不得标记完成。
