# Rust 全局约束

**版本：Ver 1.1**

本文件定义 Rust 项目开发中必须遵守的全局性约束，适用于所有模块与代码文件。

---

## 1. 编码与组织结构

目录结构、文件命名、代码结构、函数与变量命名，均遵循 Rust 社区规范。

## 2. 注释规范

为代码编写**中文注释**。注释内容与格式遵循 Rust 社区规范：

- **公开 API**：使用 `///` 编写 Markdown 文档注释，说明用途、使用示例与注意事项。
- **内部实现**：使用 `//` 解释"为什么"而非"是什么"。

## 3. 公开性约束

- 所有新添加的函数、方法、结构体成员，默认可见性为私有。当且仅当在接口定义、API 文档或公开清单中明确标注为公开时，才将其公开。
- 当且仅当显式声明时，才修改现有函数、方法、结构体成员的公开性。

## 4. 函数、方法与接口入参校验规范

- **公有接口**：须做黑盒性质的入参安全校验。
- **公有函数**：须做白盒性质的入参安全校验。
- **私有函数**：不做入参安全校验。
- **原则**：简洁优先。

## 5. 禁止过度工程化

遵循奥卡姆剃刀原则：*"如无必要，勿增实体"*。禁止出现以下行为：

- 禁止为"未来可能"提前添加架构
- 禁止抽象层过多
- 禁止过度解耦
- 禁止扩展点远多于真实用法
- 禁止通用库 / 共享库失控
- 禁止测试和 CI 过度膨胀
- 禁止为添加模式而添加模式

## 6. 错误处理原则

- 错误传播遵循 Rust 社区规范：可恢复错误使用 `Result`，不可恢复错误使用 `panic`。
- 禁止静默吞错（如 `let _` 修饰错误），确有忽略需求时须注明理由。

## 7. 安全红线

- 禁用 `unsafe`，确需使用时须显式评估并注释说明原因。
- 不使用 `unwrap()`/`expect()` 处理外部输入。

## 8. 性能与资源

- 避免在热路径上进行不必要的堆分配或克隆。
- 优先使用借用与引用而非所有权转移，遵循借用检查器语义。

## 9. 测试规范

- 每个公开 API 必须配套单元测试。
- 关键模块需有文档测试（`/// # Examples`）。
- 修复的 bug 必须补充回归测试。
- **测试代码与源码隔离**：任何文件不得同时包含生产源码与测试代码。

## 10. 提交与协作

- 提交信息遵循 Conventional Commits（`feat`/`fix`/`refactor`/`docs` 等）。
- 提交前后运行 `cargo fmt`、`cargo clippy` 与 `cargo test`。

## 11. 文档同步

- 修改公开 API 时须同步更新文档注释与 README，保持"代码即文档"风格。
