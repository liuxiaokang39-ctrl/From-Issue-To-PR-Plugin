# Rust 全局约束（Ver 1.1）

本文件定义 Rust 项目开发中必须遵守的强制约束，适用于所有模块与代码文件。全文仅含 必须（MUST）与 禁止（MUST NOT）两类约束。

---

## 1. 编码与组织结构

- 必须（MUST）遵循 Rust 社区规范进行目录结构、文件命名、代码结构及函数与变量命名。

## 2. 注释规范

- 必须（MUST）使用中文编写注释。
- 必须（MUST）为公开 API 使用 `///` 编写 Markdown 文档注释，说明用途、示例与注意事项。
- 必须（MUST）为内部实现使用 `//` 解释"为什么"而非"是什么"。

## 3. 公开性约束

- 必须（MUST）将所有新添加的函数、方法、结构体成员的可见性默认设为私有。当且仅当在接口定义、API 文档或公开清单中明确标注为公开时，才将其公开。
- 必须（MUST）仅在显式声明时，才修改现有函数、方法、结构体成员的公开性。

## 4. 入参校验规范

- 必须（MUST）为公有接口做黑盒性质的入参安全校验。
- 必须（MUST）为公有函数做白盒性质的入参安全校验。
- 禁止（MUST NOT）为私有函数做入参安全校验。
- 必须（MUST）以简洁优先。

## 5. 禁止过度工程化

- 必须（MUST）遵循奥卡姆剃刀原则：*"如无必要，勿增实体"*。
- 禁止（MUST NOT）为"未来可能"提前添加架构。
- 禁止（MUST NOT）抽象层过多。
- 禁止（MUST NOT）过度解耦。
- 禁止（MUST NOT）扩展点远多于真实用法。
- 禁止（MUST NOT）通用库 / 共享库失控。
- 禁止（MUST NOT）测试和 CI 过度膨胀。
- 禁止（MUST NOT）为添加模式而添加模式。

## 6. 错误处理原则

- 必须（MUST）遵循 Rust 社区规范传播错误：可恢复错误使用 `Result`，不可恢复错误使用 `panic`。
- 禁止（MUST NOT）静默吞错（如 `let _` 修饰错误）。确需忽略时，必须（MUST）注明理由。

## 7. 安全红线

- 禁止（MUST NOT）使用 `unsafe`。确需使用时，必须（MUST）显式评估并注释说明原因。
- 禁止（MUST NOT）对外部输入使用 `unwrap()`/`expect()`。

## 8. 性能与资源

- 必须（MUST）避免在热路径上进行不必要的堆分配或克隆。
- 必须（MUST）优先使用借用与引用而非所有权转移，遵循借用检查器语义。

## 9. 测试规范

- 必须（MUST）为每个公开 API 配套单元测试。
- 必须（MUST）为关键模块提供文档测试（`/// # Examples`）。
- 必须（MUST）为修复的 bug 补充回归测试。
- 必须（MUST）将测试代码与源码隔离：禁止（MUST NOT）在同一文件中同时包含生产源码与测试代码。

## 10. 提交与协作

- 必须（MUST）遵循 Conventional Commits（`feat`/`fix`/`refactor`/`docs` 等）。
- 必须（MUST）在提交前后运行 `cargo fmt`、`cargo clippy` 与 `cargo test`。

## 11. 文档同步

- 必须（MUST）在修改公开 API 时同步更新文档注释与 README，保持"代码即文档"风格。
