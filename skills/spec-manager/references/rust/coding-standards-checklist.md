# Rust 编码规范检查项与来源标注口径

本文件供 `spec-manager` 在第 2 步生成或更新 `docs/dev-standards/rust-coding-standards.md` 时使用。规范的每条约束必须标注来源，二选一：

| 来源标注 | 判定条件 |
| --- | --- |
| `现状归纳` | 代码库中多数同类写法一致，且能指向具体文件或模块作为例证 |
| `实践补齐` | 代码库缺失该约定，或现有写法明显不规范、互相冲突；采用通用 Rust 最佳实践 |

标注格式：每条约束末尾附 `（来源：现状归纳，例：src/error.rs）` 或 `（来源：实践补齐）`。同一章节内不得出现无来源标注的约束。

## 一、命名

| 检查项 | 判定口径 |
| --- | --- |
| 类型与 trait | 大驼峰（`CamelCase`），trait 不以 `I` 前缀命名 |
| 函数、方法、变量、模块 | 蛇形（`snake_case`） |
| 常量与静态量 | 全大写蛇形（`SCREAMING_SNAKE_CASE`） |
| 生命周期参数 | 短小写字母，如 `'a`、`'de` |
| 布尔与谓词 | 以 `is_`、`has_`、`can_` 等开头，命名体现判定语义 |
| 转换方法 | 按惯例区分 `as_`（借用转换）、`to_`（复制转换）、`into_`（所有权转换） |

## 二、错误处理

| 检查项 | 判定口径 |
| --- | --- |
| 库代码错误类型 | 使用自定义 `enum` 并实现 `std::error::Error`，禁止在库代码中使用 `Box<dyn Error>` 作为对外错误类型 |
| 可恢复错误 | 返回 `Result<T, E>`，禁止用 `panic!` / `unwrap()` / `expect()` 处理可恢复错误 |
| 不可恢复错误 | 仅在不变量被破坏时使用 `assert!` / `panic!`，并在文档注释中说明前提 |
| 错误传播 | 使用 `?` 传播，保留原始错误上下文；禁止只返回字符串错误而丢失来源 |
| 错误信息 | 面向用户的错误信息说明「发生了什么 + 可采取的动作」，不泄露内部路径与堆栈 |

## 三、所有权与借用

| 检查项 | 判定口径 |
| --- | --- |
| 参数传递 | 只读借用用 `&T`，需要所有权时用 `T`，禁止无理由使用 `&String` / `&Vec<T>` 代替 `&str` / `&[T]` |
| 返回借用 | 返回借用时生命周期必须能由入参唯一确定，禁止返回指向局部数据的引用 |
| 克隆 | 禁止以 `clone()` 掩盖借用设计问题；确需克隆时在代码注释中说明原因 |
| 内部可变性 | 优先使用 `&mut`；仅在共享可变状态确有必要时使用 `Rc<RefCell<T>>` / `Arc<Mutex<T>>`，并说明并发语义 |
| 智能指针选择 | 单线程共享用 `Rc`，跨线程共享用 `Arc`；需要弱引用防环时使用 `Weak` |

## 四、文档注释

| 检查项 | 判定口径 |
| --- | --- |
| 公有项覆盖 | 所有 `pub` 类型、函数、常量、模块都要有 `///` 文档注释 |
| 结构 | 函数注释至少包含功能说明；有参数、返回值或错误时，分别用 `# Arguments`、`# Returns`、`# Errors` 小节 |
| 示例 | 关键公有 API 提供 `# Examples`，示例代码须为可编译代码块 |
| 内部说明 | 非公有实现细节用 `//` 注释，只解释「为什么」，不重复代码已表达的内容 |
| 模块级说明 | 模块顶部用 `//!` 说明职责与使用方式 |

## 五、模块组织与可见性

| 检查项 | 判定口径 |
| --- | --- |
| 模块拆分 | 按职责拆分模块，禁止出现同时承担多个不相关职责的巨型模块 |
| 可见性最小化 | 默认私有，仅在确需跨文件或跨模块使用时才提升可见性；禁止无理由 `pub` |
| 重导出 | `pub use` 只用于稳定对外 API 边界，禁止为图方便随意重导出内部实现 |
| 文件规模 | 单文件职责单一；文件过长（超过 800 行）时按职责拆分 |
| 依赖方向 | 模块依赖单向，禁止出现循环依赖 |

## 更新已有规范时的处理

- 只为与现状不一致的条目产生变更，其余条目保持不变；
- 每条变更记录「原约束 → 新约束 → 变更原因」，供第 4 步写入迁移信息；
- 规范文档内只保留更新后的最新约束，不保留被替换的旧条目。
